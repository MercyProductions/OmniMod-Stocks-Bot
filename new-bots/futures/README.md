This is a dedicated Futures research bot with separate market-context and day-strategy paths. Market context defaults to manual observations. An optional Databento Historical API adapter can fetch cost-capped 1-minute and daily OHLCV for continuous-symbol research (`FUTURES_SOURCE=databento`); it is not a streaming quote, active-contract selector, or executable price feed. Set an API key and a positive `FUTURES_MAX_SCAN_COST_USD` to enable it. Before downloading, the adapter requests cost estimates for both schemas and rejects the scan if their sum exceeds the configured per-scan cap. The provider estimate is not an absolute billing guarantee; review Databento's current pricing and account entitlements. Manual mode makes no Databento requests.

The day path evaluates a 15-minute opening-range breakout with H1 EMA20/EMA50 trend, relative-volume confirmation, executable quote spread in ticks, and tick-rounded entry/stop/target levels. H1 bars may be fetched from Databento Historical with `FUTURES_TREND_DATA_SOURCE=databento-historical`; the adapter requests a cost estimate first and uses only the remaining `FUTURES_MAX_SCAN_COST_USD` per-scan cap. It requires at least 50 completed, fresh hourly bars for each exact verified active-contract raw symbol, and blocks incomplete rows before strategy evaluation. Accepted proposals pass through the shared paper risk ledger and later timestamped marks can fill or exit them. There is no broker or live order interface. Automated Yahoo Chart access is disabled.

The Futures strategy accepts numeric contract specs, account equity, quote prices/sizes, and bar OHLCV only as finite numbers or nonblank numeric strings. Malformed fields are rejected before strategy approval. For Databento Live MBP-1 entry data, both displayed top-of-book sizes must cover the paper-sized quantity; this is a screening check, not guaranteed executable depth or a fill guarantee.

If the shared primary-signal journal is available, the runner attaches fresh Stocks/Crypto records whose symbols match a day input's declared `contract.exposureKey` (for example, SPY research to an ES/MES contract configured with `SPY`). `FUTURES_PRIMARY_SIGNAL_MAX_AGE_MS` sets the maximum age (default five minutes, capped at one hour). This is descriptive research context only: it does not affect strategy qualification, catalyst clearance, sizing, or risk approval. Missing/unreadable journal data does not block Futures scans.

The 36-product sample universe contains Databento continuous symbology identifiers only; they map to changing contracts and are not refreshed by a real-time feed or eligible for the day-strategy path. It covers standard and micro U.S. equity-index products (ES/MES, NQ/MNQ, RTY/M2K, YM/MYM), WTI crude (CL/MCL), natural gas (NG), gold (GC/MGC), silver (SI), Treasury notes/bonds (ZN/ZB), major currency futures (6E/6J), and standard, mini, and micro agricultural contracts for corn, soybeans, Chicago/KC wheat, soybean oil/meal, and livestock. The default scan cap covers all 36 rows; provider-backed historical scans require a positive total cost cap, while contract discovery remains opt-in. Smaller contract units broaden research but do not imply active status, liquidity, margin, or lower account-risk suitability. CME product references: [Micro E-mini equity-index contracts](https://www.cmegroup.com/markets/equities/micro-emini-equity.html), [Micro WTI specifications](https://www.cmegroup.com/education/articles-and-reports/micro-wti-crude-oil-futures-faq), and [Micro Gold specifications](https://www.cmegroup.com/trading/metals/files/fact-card-gold-futures-options.pdf). Mocked request tests confirm the scanner submits configured micro and agricultural `.FUT` parent roots to Databento after the cost estimate; real symbol resolution and account coverage remain untested. CME agricultural references include the [Micro Ag FAQ](https://www.cmegroup.com/articles/faqs/faq-micro-agriculture-futures.html), [current CME product slate](https://www.cmegroup.com/markets/products), and [Grain/Oilseed product codes](https://www.cmegroup.com/trading/agricultural/files/grain-and-oilseed-futures-options-fact-card.pdf). Databento continuous symbols follow its documented `[ROOT].v.[RANK]` convention and GLBX.MDP3 supports parent and continuous symbology ([Databento symbology](https://databento.com/docs/standards-and-conventions/symbology)). The adapter labels observations research-only and rejects stale/future-dated bars. The day path requires a manually supplied active-contract ID and expiry (date-only `YYYY-MM-DD` or timezone-qualified ISO timestamp), recently verified tick size/value, multiplier, initial/maintenance margin, session bars/calendar, executable quote, costs, account equity, a fresh source-backed catalyst review, and a canonical `exposureKey` aligned with other bots (for example, `SPY` for S&P 500 cross-product exposure). Date-only expiry is treated as UTC midnight conservatively; ISO timestamps preserve the exact provider instant. The Databento history adapter does not supply or verify these fields; missing or inconsistent data fails closed. When optional dated-definition discovery is enabled, the scan now reconciles configured raw symbols, expiries, tick size/value, and multiplier against the provider definitions and reports missing definitions/mismatches. The reconciliation is advisory only and never verifies active status, margins, session, settlement, liquidity, or trade eligibility.

The default discovery scope is now `FUTURES_CONTRACT_DISCOVERY_SCOPE=dataset`: it discovers `ALL_SYMBOLS` historical definitions independently of the configured priorities, classifies every returned identity and archives exclusions. Run `npm run probe:directory --prefix futures` for metadata/cost only; run `npm run discover:contracts --prefix futures` only with a configured key and explicitly positive cost cap for the actual directory download. Scheduled refresh remains opt-in. Dataset discovery keeps all unexpired outright references unverified and ineligible; `providerTickValue` is unknown pending independent contract review. The old curated `.FUT` mode remains available with scope `configured_roots`, and the volume-ranked review-draft helper remains curated. See [dataset-directory handoff](DATASET_DIRECTORY.md) for exact behavior, setup, resource limits, cache/archives and remaining broad live-screening work. Actual local account coverage is unknown because the provider key is absent.

To turn saved definitions into a review worksheet without editing the configured session file, run `npm run prepare:day-session --prefix futures -- <definitions.json> > <draft.json>`. The draft preserves provider-reported tick/multiplier data only in `providerReference`; strategy-trusted contract terms, broker ID, margin, exposure key, session, settlement, catalyst clearance, bars, quote, fees, and slippage remain null, blocked, or empty. It is explicitly marked `draft: true` and fails the active-contract validator until completed. Definitions must carry a valid provider timestamp no more than 24 hours old; missing, future, invalid, and stale definitions are rejected with structured reason codes before they reach the review worksheet. Each other malformed, expired, unsupported-product, missing-identity, or duplicate raw-symbol row also appears in `rejectedDefinitions`; valid rows remain available as unverified review drafts. A partial result sets `partial: true`, prints a warning to stderr, and exits nonzero so the rejection list is not missed. It does not decide which unexpired contract is actively traded; select and verify contracts independently, complete every checklist item, and use `review:contracts` before configuring paper day scans.

For a single cost-capped discovery-to-review step, run `npm run discover:day-session-draft --prefix futures`. It asks Databento for continuous `[ROOT].v.0` definitions, resolving the prior trading session's volume-ranked expiry per configured root, after checking the estimated data cost against the positive `FUTURES_MAX_SCAN_COST_USD` cap. It emits mappings, provider metrics, and an unverified worksheet to stdout without writing the configured day-session file. `tradeEligibleContracts` is always zero; each draft still needs current-session liquidity, contract identity/specification, margin, session, catalyst, executable quote, fee, and slippage review. It does not create a paper trade or broker order.

If an unfinished worksheet is supplied as the configured day-session file, the runner skips rows marked `draft_requires_manual_review` before requesting day-session, H1, or economic-calendar data. The structured report marks the state `draft_contracts_only`, includes `draftsSkipped`, and reports `no_day_trades` for those feeds. An approved row must be independently verified and have the draft marker removed before it can enter the day-scan path.

After discovery, run `npm run review:contracts -- <discovery-output-or-cache.json> <day-session.json>` to compare provider raw symbols, exact expiry instants, provider and configured tick/multiplier terms, definition freshness, configured spec source/timestamp, tick value, initial/maintenance margin, and settlement evidence. Each configured day-trade contract must include `specSource` as an HTTPS URL and timezone-qualified `specVerifiedAt` alongside its verified tick/multiplier/tick-value/margin values. It also needs a `settlementReview` object with `settlementType` (`cash_settled` or `physical_delivery`), an HTTPS source URL, timezone-qualified `reviewedAt`, and future `lastTradeAt`; physical-delivery contracts need future `firstNoticeAt`. The report includes the exact provider/configured numeric terms and spec provenance it compared, flags missing/stale evidence and mismatches, and never edits inputs or promotes contracts to trade eligibility. HTTPS syntax is checked, but URLs are not fetched or authenticated and their cited content still needs human review. The active-contract ORB gate now independently requires the same valid, source-backed settlement review at entry time, rejects stale/future reviews and last-trade timestamps beyond the configured expiry, and blocks physical-delivery contracts after first notice and, by default, within 24 hours of the earlier of first notice or last trade (cash-settled contracts use last trade). Configure `FUTURES_DELIVERY_ENTRY_BUFFER_HOURS` from 0 to 720 hours to set the cutoff buffer; invalid values fail closed. The report and paper-order record retain the effective entry cutoff and buffer. The live candidate scan must still verify fresh executable quotes, active status and displayed size.

Each runner scan also checks reserved/open paper Futures rows for expired contracts, passed last-trade/first-notice cutoffs, cutoffs within 24 hours, missing/invalid contract terms, specs older than 90 days, and stale settlement reviews. Warnings are persisted and included in the webhook and CLI report. This does not infer exchange calendars, liquidate positions, calculate settlement P&L, or replace broker/exchange lifecycle handling.

For an already verified contract/session row, `FUTURES_DAY_DATA_SOURCE=databento-live` opts the paper runner into the Databento Live Raw feed for entry inputs. It requests `ohlcv-1m` replay from the configured exchange-session open and current `mbp-1` updates in one connection, waits for both the replay-complete system record and a fresh quote, then aggregates only five consecutive complete one-minute records into a five-minute bar. Missing minutes, stale/crossed quotes, thin displayed top size, unresolved symbols, or replay/session windows outside the Live API's recent-replay allowance prevent paper candidate approval. Active contract tick/multiplier/margin verification, exchange session times and catalyst review remain required configured inputs. The quote book size is checked against risk-sized contract quantity before reservation; MBP-1 top size remains an estimate, not guaranteed fillable depth. This path requires a licensed Databento Live entitlement and has only been exercised with a protocol mock here, not an authenticated account.

Mapped currency-futures roots share the paper ledger's currency-leg concentration gate with Forex pairs (for example, CME 6J mapped to USD/JPY). Same-direction currency overlap is blocked; opposite leg exposure can offset and remains eligible subject to all other portfolio limits. This is a conservative overlap check, not a calibrated cross-market correlation model.

To run one scan, configure this bot’s `.env` and run `npm run scan`. `npm start` connects the separate Futures application and repeats scans at `SCAN_INTERVAL_MINUTES`. The universe is `FUTURES_FILE`; contract/session context is in `FUTURES_DAY_SESSION_FILE` (default `examples/day-session.json`). Each `dayTrades` row supplies a verified contract, exchange `session`, and `catalystReview` object such as `{ "status": "clear", "source": "CME notices", "summary": "No known contract disruption or scheduled event in the entry window.", "reviewedAt": "2026-09-29T14:45:00Z" }`. A trade-eligible `session` must include `source` as a credential-free HTTPS URL and `reviewedAt` no older than 24 hours; the accepted source and timestamp are copied into paper-candidate provenance. Sessions longer than 24 hours fail closed. This proves only that the operator supplied a fresh cited source, not that the URL's contents, exchange hours, holidays, or early closes were independently authenticated. Manual trend mode supplies completed hourly `trendBars`; optional `FUTURES_TREND_DATA_SOURCE=databento-historical` fetches them by exact raw symbol within the remaining per-scan cost cap and rejects insufficient or stale data. Manual day mode also requires five-minute `bars` and an executable `quote`; `FUTURES_DAY_DATA_SOURCE=databento-live` replaces those fields with provider data. Session timestamps must match `session.timeZone` and `marketDate` (the open may fall on the prior local date for an overnight session, while close must fall on the declared market date). Catalyst review timestamps must be no older than 30 minutes. Missing, blocked, malformed, stale, or future-dated session/catalyst reviews fail closed. Manual review remains the default. Optionally, `FUTURES_CATALYST_SOURCE=finnhub` requests scheduled US macro events and blocks on unavailable coverage or medium/high-impact events; this is not company/commodity news or an exchange session calendar. Fallback macro-calendar query dates and paper-performance dates use the America/Chicago local date. `marks` advances reserved/filled paper rows using `{ orderId, quote, sessionOpen }`.

The example day-session file currently contains zero `dayTrades`. In that configuration, the 36-product context scan is not a Futures day-opportunity scan: no product reaches the ORB/H1 strategy. The bot reports `no_configured_day_contracts` explicitly. Optional Databento definitions provide dated identity/spec references only; they do not auto-create day trades. An operator must supply currently verified active-contract, margin, settlement, session, catalyst, and exposure inputs before a contract is eligible for the paper strategy. Automatic active-contract discovery and session/catalyst preparation remain unfinished.

For optional read-only open-position quotes, set `FUTURES_POSITION_MARK_SOURCE=databento-live`, `DATABENTO_API_KEY`, and `DATABENTO_DATASET=GLBX.MDP3`. This uses Databento's Raw Live API over its documented TCP gateway, authenticates with its challenge-response protocol, subscribes to MBP-1 for exact `providerRawSymbol` values already attached to active paper orders, then disconnects after one valid fresh top-of-book quote per contract or an 8-second timeout. New paper candidate metadata retains `providerRawSymbol` only when it was explicitly supplied with the independently verified active contract; no continuous symbol is promoted into an order contract. The adapter checks provider timestamps, transport lag, quote sides, verified tick alignment, and displayed top-level size aggregated across the same contract's open paper units. It is intentionally opt-in, never runs for candidate discovery, and never sends orders. A live feed entitlement and exchange redistribution/use permissions are required; data charges and access depend on the Databento account. Missing key, unsupported entitlement, unknown raw symbol, stale data, or low displayed size leaves the position unmarked. Historical-only Databento access does not satisfy this Live API requirement. Live data has not been tested against an entitled account in this workspace. See Databento's [Live API](https://databento.com/docs/api-reference-live?live=raw), [MBP-1 schema](https://databento.com/docs/schemas-and-data-formats/mbp-1), and [continuous-symbol behavior](https://databento.com/docs/standards-and-conventions/symbology).

The existing Futures day strategy can be replayed offline with `npm run backtest -- path-to-replay.json` (or set `FUTURES_REPLAY_FILE`). The JSON object contains `contract`, `accountEquityUsd`, `config`, optional `policy`/`scoreFrom`, `fiveMinuteBars`, and ordered `observations`. Each five-minute bar has `time`, `completedAt`, OHLC and `volume`; each observation has `asOf`, an executable `quote`, and `context` containing point-in-time `trendBars`, `session`, and source-backed `catalystReview` (a per-observation `contract` may override the top-level contract). The runner performs no network calls and uses the production Futures ORB strategy, validates contract metadata as of each historical decision, then applies the shared paper risk and later-quote lifecycle. It reports costs, expectancy, drawdown, sampled MAE/MFE, rejection reasons, and unresolved positions. Supply only point-in-time data you are licensed to use. Synthetic fixtures verify the pipeline but do not count as performance evidence; no exchange-grade historical contract/quote dataset is currently configured.

Fees, slippage, account equity, and shared-ledger path must be configured; the emergency stop defaults active. Databento history is available only when explicitly selected, keyed, and cost-capped; no provider-backed active-contract or executable quote source is configured. Exchange-grade active-contract data requires a separately licensed feed and verified exchange permissions.

Futures use leverage and may gap quickly. Margin approval in the manual path is an input check, not a broker buying-power or liquidation model. Brokerage-specific commissions, exchange-calendar validation, roll handling, market impact, and fill quality are not fully modeled. The replay adapter is verified only against synthetic fixtures; the strategy has not been evaluated on historical market data or validated out of sample. Continuous-price observations and paper candidates are research, not investment recommendations or live orders.

The manual context path reports supplied-observation age and scan duration. Historical Yahoo adapter telemetry tests remain in the repository, but the Futures runner no longer imports or calls that adapter.

Optional scheduled macro-event screening: FUTURES_CATALYST_SOURCE=finnhub uses the same Finnhub Economic Calendar Premium entitlement as Forex. For each configured day contract, it conservatively blocks paper qualification on a medium/high-impact US event in the market date and either adjacent date. Missing credentials, malformed events, or provider errors block candidates. The calendar does not cover exchange-specific halts/notices, contract rolls, commodity supply events, or provider fill risks; manually verified contract/session metadata remains required. manual remains default and performs no Finnhub request.

The optional dated-definition cache is scoped to both the configured Databento dataset and product roots. Switching datasets invalidates the cache; a cached definition is shown only as an unverified reference and is never treated as an active contract.

To advance a provider draft into the Futures runner's reviewed paper-input schema, first save a draft without editing its contents. Run `npm run template:day-session-review -- <draft.json> > <review.json>` to create an approval template bound to the exact draft SHA-256. Fill it using current primary exchange/broker references: contract ID, active status, expiry/specs, margins, settlement/first-notice terms, dated exchange session, clear catalyst review, and round-trip commission/slippage reserves. Then run `npm run compile:day-session-review -- <draft.json> <review.json> <new-day-session.json>`. The compiler writes only a new file (`wx`; it will not overwrite an existing file or either input) and rejects a changed draft, duplicate contract, stale/invalid timestamp, inconsistent tick value, missing source, non-clear catalyst, invalid session, or missing cost reserve. It does not verify that cited pages are truthful, invent current bars/quotes, authenticate to Databento, or enable a setup. Configure the resulting path with `FUTURES_DAY_SESSION_FILE`, and separately configure entitled live/H1 feeds; the normal per-scan catalyst, market-data, strategy, shared-risk, and emergency-stop gates still apply. See `test/reviewed-day-session.test.js`.
