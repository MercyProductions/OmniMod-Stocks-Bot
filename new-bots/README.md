# OmniMod trading research workspace

The six primary paper day-trading bots have one owner per market: Stocks (`../stocks-bot`), Crypto (`../crypto-bot`), Forex, Futures, Options, and ETFs/ETPs. The last four projects live in this folder; all six use the shared paper-risk ledger when correctly configured. Paper reservations and marks are not broker execution, and live trading remains disabled.

This folder also contains four supplemental read-only research projects: Multi-Asset, Prediction Markets, DeFi Yield, and On-Chain Inefficiencies. They do not reserve or execute positions in the six-market ledger and must not be treated as additional primary owners. Multi-Asset's optional Tradier screen is a research-only options view; the Options bot remains the primary options owner. Supplemental Discord webhooks are optional and may post research summaries, not approved trades. No project stores wallet keys, signs transactions, or sends broker/exchange orders. Scores are screening rules until point-in-time data and enough out-of-sample outcomes support calibrated probabilities.

## Projects

Forex, Futures, Options and ETFs/ETPs currently have separate Windows sign-in tasks. Use `npm run shutdown` inside a bot's directory for graceful maintenance, then start that bot's `OmniMod-<bot>-Discord` task again. Task registration and real independent restarts are verified; actual OS reboot/logoff recovery is not. The PC must be awake with the user signed in, and same-boot crashed locks require review. Stocks/Crypto remain on the existing website host pending its deployment-path check. See [runtime operations and verification](DISCORD_APPLICATION_MIGRATION.md).

### Primary day-trading bots

- `../stocks-bot` and `../crypto-bot`: tactical paper setups are separate from their longer-horizon research and use the shared paper-risk path when configured.
- `forex`: standalone day-trading runner is disabled until OANDA Practice is configured. Its day-trade path uses fresh OANDA quotes/candles; USD risk sizing supports USD-quoted pairs directly and common non-USD quote currencies through fresh OANDA conversion-pair quotes. Unsupported or stale conversions fail closed. Yahoo FX context elsewhere in this workspace is delayed/reference-only and is not a fallback trade feed.
- `futures`: active-contract 15-minute opening-range strategy and shared paper risk/margin lifecycle. An opt-in, cost-capped Databento definition refresh can list unexpired outright contract identities in the scan report; it does not select/promote a contract or supply its verified margin/session/executable quote. Day inputs and active contract specs remain manually supplied. Yahoo continuous symbols remain context-only proxies; no broker order route is connected.
- `etfs-etps`: separate ETF/ETP 15-minute opening-range breakout and paper runner. Optional Alpaca mode checks clock/calendar and active tradability, fetches bulk quotes/bars/news, and requires SIP quote quality plus a fresh per-symbol manual catalyst clearance. IEX is screening-only; universe is curated, not comprehensive.
- `options`: underlying-signal-driven debit-vertical strategy and shared paper runner. Optional Tradier production mode checks session clock and fetches underlying quotes/option chains after fresh catalyst clearance; sandbox's delayed data is blocked. IV/Greeks management and calibrated fill validation remain unfinished.

### Supplemental read-only research projects

- `prediction-markets`: inspect binary-market books for possible complete-set pricing discrepancies; Polymarket estimates use market-specific taker fees when the schedule is available, while cross-venue comparisons remain gross-only until both venues' fees are verified.
- `defi-yield`: rank stablecoin lending observations while marking whether upstream timestamps are available; APY is variable, not promised income.
- `onchain-inefficiencies`: read same-block circular-route quotes from a default public Ethereum RPC and official Uniswap V2 router, subtract configured gas/slippage reserves, and flag possible net edges; assumptions still need calibration for each route, and there is no wallet or transaction path.
- `multi-asset`: optional cross-asset context scanner. `MARKET_SOURCE=manual` is the only enabled market source; supply timestamped observations in `MARKET_FILE`. Yahoo Chart discovery is disabled. A separate optional, read-only Tradier screen can inspect up to 12 configured option underlyings, but it is not the primary Options bot, does not reserve positions, and does not send orders. Sample markets and option chains are not comprehensive.

Each project runs independently with Node.js 22.9 or newer. Install the common dependency once with `npm ci` in `new-bots`. For Forex, Futures, Options and ETFs/ETPs, put that application's token, client ID, guild ID and channel ID in its own ignored `.env`, then run `npm run setup`, `npm run register`, and `npm start` from its directory. The gateway stays connected while one existing scanner child runs at a time; each bot has its own lock, redacted rotating log and heartbeat. `npm run scan` remains a one-shot scan. `npm run start:legacy` is an explicit legacy scheduler and must not run beside the application's scheduler. Application delivery verifies identity and channel/guild membership and never falls back to a webhook on failure. Supplemental projects retain optional webhooks. See [Discord application migration](DISCORD_APPLICATION_MIGRATION.md) for operational commands, verification and remaining deployment work.

Run `npm test` at this folder to run all project and shared-helper checks, or run it inside an individual project. Run `npm run check` to syntax-check every JavaScript source, script, and test file in the workspace. The tests cover book-depth, reviewed market-rule mapping expiry, conservative APY ranking, same-block quote economics, directional scenario geometry, input freshness, futures-universe validation, alert cooldown behavior, paper-risk limits, concurrent exposure reservations, and the ETF/ETP opening-range rules.

Run `npm run report:operator` for local scan/provider/readiness diagnostics. Run `npm run report:research` for a read-only JSON research summary of the shared paper ledger and latest scan gates, or `npm run report:research -- C:\path\to\research-dashboard.html` to create a self-contained local HTML dashboard. The dashboard groups costed closed paper trades by bot, strategy, instrument, UTC entry hour and weekday, and labels missing risk, cost, timestamps, market-regime and volatility-regime data as unavailable. It does not infer live fills or strategy profitability. Neither command changes bot strategy or places orders.

The research dashboard also shows current gross open paper risk and ledger notional by declared asset class and recorded effective underlying long/short direction. A missing ledger is shown as unavailable, not a verified zero. These views are nominal, omit option delta and changing ETF constituent weights, and grant no hedge or correlation credit.

The dashboard's observed setup comparison ranks highest and lowest mean realized R only when at least two setup cohorts each have 30 closed trades across five distinct UTC entry dates, valid research context no later than every fill, fully reconciled modeled costs, explicit positive initial risk, and unique close chronology. Other setup cohorts remain visible but unranked with reasons. This is a descriptive ordering of quote-sampled paper results, not a significance test, a causal comparison, or a strategy-promotion decision.

The dashboard also derives a post-trade review record for every closed paper order. It checks gross-to-net cost accounting, identifies observed stop/time exits, quote-path coverage and missing issuance context, and puts all closed trades in a review queue. A cost reserve reversing a positive gross outcome is a recorded arithmetic fact; a false breakout, poor stop, catalyst shock, invalid thesis or strategy bug cannot be diagnosed from the ledger alone. Those causes and thesis validity stay unresolved until an operator records an evidence-dated assessment in the separate review journal. The review queue does not change approval or sizing.

Use `npm run review:paper -- <review-input.json>` to append a cited manual assessment of a closed shared-paper order. The read-only dashboard validates the review journal against the unchanged closed order, shows accepted assessments as operator judgments, and flags invalid or stale journal rows. See [PAPER_TRADE_REVIEW.md](PAPER_TRADE_REVIEW.md) for the input contract and correction procedure. Reviews never change strategy gates or promote experiments.

New paper reservations also retain a bounded `researchContext` with the setup family, known issuance-time market/volatility regime labels, candidate quote timestamp and finite strategy features. Stocks and Crypto pass their existing market labels; the other four currently pass setup features but leave market regime unknown. The ledger sanitizes this context and never uses it for approval or sizing. The dashboard groups closed paper outcomes by these labels only when a valid candidate timestamp exists. Each scanner remains responsible for the freshness of the underlying features. Old rows without context remain unknown, and no regime-specific performance claim is justified until prospective cohorts have enough independent market sessions.

New paper reservations also retain `approvalEvidence`: the shared paper gate's reservation-time quote age, spread, costed reward/risk, risk budget and size, plus bounded raw score/confidence/probability fields if the source signal supplied them. The source fields are explicitly unverified raw values, not calibrated odds. Each production candidate path can add a bounded, timestamped list of market checks that its own code reports as passed. This is a partial source report, not an independently proven record of every provider, model, or upstream decision; optional gates appear only when required. Shadow variants do not inherit a production trace. Old paper orders remain unavailable rather than receiving retrospective values. The snapshot is descriptive and never changes approval, sizing or execution.

Forward-shadow profiles require an explicit `strategyVersion`, hypothesis, change, and reason in each owner. Their outcome cohort is keyed by a hash of strategy version, base configuration, and profile overrides. A write-once manifest records that definition and freezes a 60-day forward observation window only when paper equity is positive, the emergency stop is off, the market session is open, and observations exist. The first qualifying scan creates the manifest but cannot reserve its own candidates; only later candidate quotes inside the frozen window enter the cohort. Changed narrative, edited/malformed manifests, expired windows, and same-hash legacy orders with no manifest block new shadow reservations until a deliberate new version is declared. These are integrity checks against accidental mixing, not tamper-proof signatures. A version/base-config change retains the profile's ledger path; an override change creates a different hashed ledger. The runner discovers prior ledgers for that profile and continues quote-marking their open paper positions. It withholds replacement shadow entries while a prior experiment has an open position or a closed trade on the same UTC risk day. Older/unversioned/pre-freeze rows are excluded from the current cohort's metrics. Reports and scan diagnostics expose the manifest status, experiment hash and strategy version. Bump a version when strategy source semantics change without a base-config change. Historical and walk-forward results are explicitly unavailable until suitable point-in-time data is supplied; the manifest's decision remains pending manual review. This is experiment isolation, not evidence for promotion.

The prediction-market project's one-minute default is a periodic research screen. Its REST polling and public top-of-book data are not fast enough to promise micro-arbitrage or continuously manage two-sided market-making quotes. Polymarket candidate sizing includes the published market fee schedule; Kalshi cross-venue comparisons remain gross-only because the effective fee terms are not yet verified from the market feed. The on-chain project has a read-only Ethereum smoke route, but configured gas and reserve values are placeholders that must be replaced with route-specific estimates; JSON fixture mode remains available for offline testing.

## Day-trading expansion status

See [IMPLEMENTATION_PHASES.md](./IMPLEMENTATION_PHASES.md) for the six-bot acceptance checklist and verified progress. `shared/paperRisk.js` is a paper-only risk/reservation component used by Stocks, Crypto, OANDA-practice Forex, manual-session Futures, ETF/ETP, and Options paths. It is not an execution adapter. The shared risk gate canonicalizes known ETF/ETP wrappers (including leveraged/inverse and crypto-linked funds) and recognized Futures roots (ES/MES, NQ/MNQ, RTY/M2K, YM/MYM, metals, energy, major CME FX, and U.S. Treasury futures) on both risk prechecks and atomic reservations, so legacy open ledger rows also participate in cross-bot exposure checks. TLT/TMF/TMV, IEF, SHY, and recognized Treasury futures share a deliberately broad `UST_RATES` bucket; it can conservatively block distinct-tenor positions and is not a validated curve-spread/correlation model. Unknown Futures roots continue to use the configured exposure key. The emergency stop defaults active: a paper harness must explicitly set `OMNIMOD_EMERGENCY_STOP=false` after the candidate has passed its checks. `OMNIMOD_LIVE_TRADING_ENABLED=true` is rejected, and no live broker/exchange order route is implemented.

See [PROVIDER_SETUP_CHECKLIST.md](./PROVIDER_SETUP_CHECKLIST.md) for per-market local credential names, paid/free provider roles, entitlement checks, and paper setup. That checklist never requires secrets to be sent in chat.

Stocks and Crypto publish successfully delivered paper signals to the append-only `shared/signalResearch.js` journal. Related Options, ETF/ETP, and Futures reports may include up to two recent, source-attributed headlines carried by a matching Stocks/Crypto signal. Forex can also opt into fresh intraday Stocks/Crypto context through `FOREX_PRIMARY_SIGNAL_MAP_JSON`, which explicitly maps source symbols to FX pairs and leaves the native direction untranslated. Headlines and cross-market signals are unscored context only: the receiving bot still applies its own catalyst review, live quote, strategy, and shared risk gates. Records retain `paperOnly: true` and `executable: false`; no shared signal or headline authorizes a trade.

Forex, Futures, Options, and ETFs/ETPs reuse the raw Finnhub Economic Calendar response through a five-minute, same-host cache at `shared/data/finnhub-economic-calendar-cache.json`. A file lock serializes cold-cache requests across local bot processes; each bot maps the same response to its own instruments after retrieval. The cache key is a one-way token hash plus the covered date range; the credential itself is never written. Cache hits and network requests have distinct provider diagnostic operations. Expired or malformed cache data is refreshed, and a failed refresh does not fall back to stale event data or clear a catalyst gate. `OMNIMOD_ECONOMIC_CALENDAR_CACHE_PATH` can set a shared absolute cache path when the default workspace path is not appropriate. This cache is local to one shared filesystem/host, and Finnhub entitlement remains unverified.

All six bot runners now resolve their default ledger to the same absolute workspace path, independent of their process working directory. If overriding `TRADING_RISK_STATE_PATH`, use the same absolute value in every process; relative overrides are resolved against the `new-bots` workspace root. Canonical cross-market aliases include CME single-asset crypto futures (including Micro and Spot-Quoted contracts) against their Crypto spot-asset exposure keys, in addition to the listed stock-index, rates, FX, metal, and energy mappings. The CME crypto product codes are source-checked against its [Cryptocurrency Futures FAQ](https://www.cmegroup.com/articles/faqs/frequently-asked-questions-cryptocurrency-futures.html); basket/index and volatility contracts remain separate where a one-to-one underlying mapping would be misleading. Durable shadow profiles combine their own isolated virtual positions with a read-only snapshot of this common ledger for risk checks; an exact matching production signal is counted once. This is not atomic across the main and shadow ledger files, and shadow candidates are research-only. The current JSON/lock-file ledger does not coordinate separate hosts. Lock files now include PID, hostname, operation, and start time; inspect without modifying with `node shared/inspectPaperRiskLock.js [ledgerPath]`. A local missing PID is evidence to investigate, not an automatic deletion authorization; remote owners and legacy empty locks remain unverifiable. A shared transactional database and audited restart/recovery behavior are required before multi-host paper deployment.

Run `npm run report:operator` for a read-only cross-bot scan, process-heartbeat, and shared-paper-ledger report. Stocks/Crypto service processes pulse secret-free PID-specific heartbeat files into their data folders. The four scheduled runners pulse from the scheduler parent and report child scan state/next run; one-shot `npm run scan` commands only contribute scan diagnostics. Heartbeats expire after 45 seconds and include a one-way ledger-path fingerprint. The report flags whether active workers agree with its configured ledger without printing filesystem paths; this verifies configured-path agreement, not shared-filesystem reachability. Set `OMNIMOD_STOCKS_DATA_DIR` and `OMNIMOD_CRYPTO_DATA_DIR` to locate non-default data folders. The report omits guild IDs and order rows and only observes a shared ledger on the same filesystem. Portfolio and per-bot paper summaries include closed sample size, net P&L, expectancy, average win/loss, profit factor (undefined until at least one loss), average realized R when initial risk is recorded, and chronological closed-trade-sequence drawdown. Small samples are labeled descriptive; drawdown is explicitly trade-sequence P&L and excludes open/intratrade movement. Closed paper orders also report quote-sampled gross MAE/MFE averages and sample count; these exclude between-scan movement and do not represent calibrated fills. A heartbeat reports configured stop state but does not independently prove that the stop mechanism works. This report does not place or alter orders.

The operator portfolio summary also groups active paper reservations/positions by declared asset class and effective underlying long/short direction. Its direction view recognizes recorded inverse ETF/ETP and option-underlying directions; missing or unclassified metadata stays visible, and incomplete risk/notional subtotals stay unavailable. These are gross ledger amounts, not option delta-equivalent exposure, weighted ETF constituent exposure, a correlation estimate, or a hedge credit. The groups change reporting only, not reservation limits or strategy decisions.

The operator report also includes `providerReadiness`: it checks only whether expected keys/modes are present in each local `.env`, never emits credential values, and explicitly labels provider authentication/entitlement as unverified. `paperRiskStatus` separately checks the correct paper-equity variable per bot plus whether required fee/slippage assumptions are present; it does not claim that those assumptions match a real account. Stocks and Crypto equity use `OMNIMOD_PAPER_ACCOUNT_EQUITY_USD`; the four standalone runners use `PAPER_ACCOUNT_EQUITY_USD`. Crypto reports the availability of its public fallback even without paid keys. This is configuration inventory, not a provider connection test.

Each bot's latest-scan safety summary also separates live trading being disabled from `OMNIMOD_LIVE_TRADING_ENABLED=true` being requested. A request is reported as `requested-but-blocked`: the paper reservation gate rejects live mode and the research bots have no order route. Missing or stale scan records report request state as unknown.

To reconcile the same local paper ledger without waiting for a scan, first stop its owning bot process, then run `npm run recover:paper -- --confirm-owner-stopped` (defaults to the workspace ledger) or pass `<absolute-ledger-path> --confirm-owner-stopped` / set `TRADING_RISK_STATE_PATH`. The lock inspector, operator report, and paper-ledger library defaults resolve to the same workspace path. Without the explicit confirmation flag the command reports `operator_confirmation_required` and does not mutate the ledger. Recovery cancels only unfilled reservations whose entry/time deadline passed, or all pending reservations when `OMNIMOD_EMERGENCY_STOP=true`; it never closes filled positions without a fresh executable quote. If any lock file exists, it prints a manual-review result and exits without changing the lock or ledger.

`shared/chronologicalReplay.js` provides a replay harness for one fixed instrument/strategy adapter at a time. Supply strictly ordered quote observations, bars with explicit `completedAt` times, an evaluator that returns a normal paper candidate, configured account equity, and market-specific risk/cost reserves. The Forex, Futures, Options and ETF/ETP adapters also accept an optional time-bounded `executionCostSchedule`; each row supplies UTC `validFrom`/`validUntil`, round-trip fees and slippage reserve per strategy unit, and a credential-free HTTPS source URL. At every decision the adapter receives only the active row, schedule gaps block candidate evaluation, and the applied row is retained on the paper order and closed-trade report. Quote bid/ask still models observed spread; the configured schedule does not calibrate market impact, borrow, or financing. Stocks and Crypto retain their separate market-specific replay engines and do not yet use this shared variable-cost schedule. The harness rejects any observation quote timestamp after its decision timestamp, hides bars not yet completed, blocks candidate identity/quote mismatches, and uses the same shared paper risk and later-quote fill/exit lifecycle. Replay reports median, p95, and maximum gaps between input quotes and between executable quotes accepted while filled positions are monitored, plus reservation-to-fill delay with reservation timestamps aligned to the replay clock; these diagnose sampling cadence and simulated fill latency but cannot reveal unsampled intrabar movement. If each observation supplies a known `regimeKey` (risk_on, mixed, sideways, risk_off, high_volatility, or low_volatility), the output groups scored observations, no-setup results, candidates, identity/risk rejections, reservations, and closed-trade outcomes by entry-time regime; missing/unrecognized values are grouped as unknown. Closed outcomes are also grouped by actual exit reason globally and inside each regime, with closed trade count, expectancy and net R, after-cost P&L, profit factor, drawdown, tail loss, and sampled MAE/MFE. These are dependent descriptive summaries of the replay, not independent strategy comparisons. The harness performs no downloads or parameter fitting. A replay is only as reliable as its point-in-time dataset and costs; the harness alone does not establish holdout quality or strategy performance.

Stocks and Crypto can opt into shared paper reservations by setting `OMNIMOD_PAPER_ACCOUNT_EQUITY_USD` to positive paper-account equity. The four market-specific runners also use the same ledger path; candidate sizing/configuration remains separate per bot. `OMNIMOD_EMERGENCY_STOP` defaults to `true`; a local paper test must explicitly set it to `false` after reviewing limits. With no configured equity, Stocks/Crypto retain their signal/tracker workflow but do not reserve shared portfolio risk. Enabling paper reservations adds a final risk gate and quote-sampled simulated fill/exit tracking; a supplied `entryExpiresAt` must be valid, future-dated, and no later than `forceExitAt`, and the reservation boundary checks it again. Reservations also fail closed if the candidate or computed sizing/limits changed after risk approval. Account-wide daily loss uses one UTC calendar day across all six bots; each market's displayed session P&L still uses its own market date. The atomic reservation check recomputes the UTC-day realized loss from the shared ledger, so activity spanning market-local midnight cannot evade the common circuit breaker. It never enables live orders. Do not point separate users' portfolios at one shared ledger.

All bots that share a ledger must use the same dollar equity value. Stocks and Crypto configure `OMNIMOD_PAPER_ACCOUNT_EQUITY_USD`; Forex, Futures, Options, and ETFs/ETPs configure `PAPER_ACCOUNT_EQUITY_USD`. The first successful reservation permanently anchors that ledger's equity basis. Later reservations using a different equity are blocked, even after all earlier orders close. To start a cohort with a different equity, preserve the existing ledger and deliberately configure a new shared ledger path for all six bots.

All six primary bots publish up to three explicitly displayed, reserved paper setups to `OMNIMOD_SIGNAL_RESEARCH_PATH` (default `shared/data/primary-signals.jsonl`) only after their matching Discord summary is successfully delivered. Shared rows include distinct instrument and exposure identities and remain paper-only/non-executable. Forex, Futures, and ETFs/ETPs consume fresh peer-bot context by declared exposure; Options shared entry mode consumes fresh delivered Stocks and ETF/ETP day-trade signals; same-direction duplicates select the freshest source and opposing directions are withheld before chain analysis. Its own catalyst, quote, chain, assignment, and portfolio gates remain required. The writer serializes concurrent publishers, atomically compacts the journal to seven days and 5,000 records by default, and retains only rows with usable timestamps. Shared context never becomes an executable quote or qualifies a trade. If a publisher reports that the journal is locked, it does not rewrite the file; inspect the adjacent `.lock` file and remove it only after confirming its local owner process has stopped.
