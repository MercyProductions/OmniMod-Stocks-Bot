# Forex Research

This market has its own Discord application. Install dependencies with `npm ci` in the parent `new-bots` folder, configure the four `DISCORD_*` identity/destination fields in this bot’s ignored `.env`, then run `npm run setup`, `npm run register`, and `npm start` here. The application wraps the existing scanner with an isolated scheduler, heartbeat, lock and redacted log. `npm run scan` remains the one-shot market path. Use `npm run shutdown` for graceful local maintenance. Separate limited-user Windows sign-in tasks and restart instructions are documented in the linked migration guide; these require the PC to be awake and the user signed in. See [application setup and verification](../DISCORD_APPLICATION_MIGRATION.md). A connected bot does not establish market-data readiness or strategy performance.


The bot is disabled by default until an authorized source is configured. Set `FOREX_SOURCE=oanda-practice` with an OANDA practice account ID and token in the ignored local `.env` to activate M15/H1/H4/D candles and practice bid/ask pricing. The scanner reports EMA9/EMA21 direction and ATR-based reference levels; it remains paper-only and uses no order endpoints. No OANDA credentials are currently present in this workspace.

Set `FOREX_SOURCE=oanda-practice` to use OANDA v20 practice pricing instead. That mode requires an OANDA practice account ID and API token in the local ignored `.env`; it rejects the live host and never calls order endpoints. The combined bias requires all selected frames to agree, while separate frame watches can conflict. EMA/ATR levels are heuristics, not calibrated probabilities or forecasts.

Run with Node 22.9+. A stale latest bar blocks watch levels. OANDA access varies by account division and region. Revoke any account token if exposed. Automated Yahoo Chart access is disabled by default and requires a documented permission attestation; when explicitly enabled for observation, its three timeframe requests each retry one transient network/429/5xx failure at most, honor a provider delay only up to two seconds, and remain delayed/unofficial reference data without executable bid/ask. This retry behavior does not enable Yahoo access in the runner or qualify its observations for entries.
# Intraday strategy status

`src/dayStrategy.js` defines a testable M15 range breakout aligned with H1 EMA20/EMA50. It requires complete recent candles, a fresh executable bid/ask beyond the breakout level, a spread below a configured fraction of ATR, an explicit scheduled-catalyst review, quote-currency-to-USD conversion, and fee/slippage assumptions. It sets a 1.25 ATR stop, 2R target, and New York-session time exit at 16:59 ET, computed with daylight-saving changes and the provider’s daily 16:59–17:05 ET maintenance break. The rules are research hypotheses, not validated strategies.

Quote prices and candle OHLC values must be finite numbers or nonblank numeric strings. Boolean/blank market fields and strategy overrides cannot be coerced into prices or loosen spread/breakout controls; invalid candles are excluded before the minimum-history test.

The OANDA practice runner now calls this evaluator and passes candidates through the shared risk ledger. OANDA quote/candle requests record operation-level latency, cooldown wait, and HTTP/provider failure status; a 429 establishes a provider-scoped cooldown shared by concurrent Forex REST calls in the same process. This gate does not coordinate separate processes or other traffic sharing the host IP; an instrument request failure is journaled per pair so other configured pairs can still be evaluated. Later OANDA quotes advance its paper reservations, fills, and exits. Yahoo remains observation-only because it has no executable bid/ask. Both watch data paths now use the same timestamp classifier as the trade gate: timestamps more than five seconds in the future are not presented as fresh. The shared coordinator blocks new entries if any active position's last mark is older than five minutes; `FOREX_MAX_OPEN_MARK_AGE_MS` overrides that limit from 1 second to 24 hours. A Forex scan refreshes open Forex positions from its OANDA pricing request, but marks from other bots still depend on their own monitoring source. The risk ledger still fails closed by default: supply practice credentials, verified USD conversion and cost reserves, account equity, a shared ledger path, and a fresh manual scheduled-news review. Set `FOREX_CATALYST_CLEAR=true`, `FOREX_CATALYST_REVIEWED_AT` to an ISO timestamp, `FOREX_CATALYST_REVIEW_SOURCE` to the checked official source, and `FOREX_CATALYST_REVIEW_SUMMARY` to a short note. The review must be no more than 30 minutes old; missing provenance, future timestamps, or stale reviews block the candidate; explicitly disable the emergency stop only for a paper test. The strategy uses the New York market date (the next date after the 17:05 ET reopen) and OANDA US trading hours: Sunday 17:05 through Friday 16:59 ET, with the daily six-minute break. Holiday exceptions are not automatically loaded. Operators may set `FOREX_CLOSED_SESSION_DATES` to comma-separated ISO session dates, and `FOREX_EARLY_CLOSES_ET_JSON` to a JSON object such as `{"2026-12-24":"13:00"}`. These overrides are manual and must be checked against current OANDA holiday notices; malformed overrides stop startup. No trade should be inferred from the older multi-timeframe watch.

The shared paper risk gate also checks currency-leg concentration across different instruments. Same-direction exposure to a currency already present in an active Forex or mapped currency-futures position is blocked, while opposite leg exposure is allowed as a potential hedge. This is a conservative overlap rule, not a covariance, net-delta, or portfolio-volatility model; exact same-pair duplicate/conflict checks and aggregate risk/notional caps still apply.

Session gates are instrument-aware. OANDA lists TRY pairs on weekdays from 08:00 to 17:00 Central European time and an additional 06:59–07:05 maintenance pause in Auckland time for NZD pairs; the code uses `Europe/Berlin` and `Pacific/Auckland` IANA time zones so daylight-saving transitions are applied. TRY session dates and closes use the Central European calendar; New York early-close overrides do not apply to TRY pairs. Manually list TRY early-close dates under `FOREX_CLOSED_SESSION_DATES`. Confirm current [OANDA US trading hours](https://www.oanda.com/us-en/trading/hours-of-operation/) and [holiday notices](https://www.oanda.com/us-en/trading/holiday-trading-hours/) before relying on a session gate, since holiday schedules can change. Session timezone, schedule, open/closed status, and NZD-break state are included in pair diagnostics.

Optional cross-market research: `FOREX_PRIMARY_SIGNAL_MAP_JSON` maps each FX pair to explicitly related Stocks/Crypto symbols, for example `{"EUR_USD":["FXE"]}`. In OANDA Practice mode the runner reads fresh signal-journal records (default maximum age five minutes) and attaches only active, recognized intraday, paper-only, non-executable signals for mapped symbols. Reports show each source's native direction and label it unscored; they never translate that direction into a Forex-pair bias or pass it into strategy/risk approval. An empty mapping shares nothing. Configure `OMNIMOD_SIGNAL_RESEARCH_PATH` consistently across bots to use the shared journal. Mapping is an operator assertion of relevance, not a learned correlation model.

With `FOREX_DYNAMIC_DISCOVERY=true`, every valid account-listed CURRENCY instrument is screened, including non-G10 pairs. Metals, CFDs and malformed identities have explicit membership exclusions. OANDA documents an unpaginated, account-specific [instrument directory](https://developer.oanda.com/rest-live-v20/account-ep/); this is account coverage, not a claim to all global FX instruments. Metadata refreshes hourly by default (`FOREX_DIRECTORY_REFRESH_MS`, 60,000–86,400,000). The atomic cache is scoped by a hash of the practice account ID, stores no credentials, and retains the latest directory plus 30 refresh deltas for added/removed/changed instruments. A failed expired-directory refresh withholds new analysis; it does not fall back to an unverified configured list.

Every scan requests fresh [pricing](https://developer.oanda.com/rest-live-v20/pricing-ep/) for all eligible account FX in batches of at most 50 (our request bound). Configured pairs receive priority only after passing the same freshness, tradeability, valid-spread and existing spread-limit screen. Other pairs rank by relative spread. `FOREX_MAX_SCAN_INSTRUMENTS=20` bounds expensive history downloads, not discovery membership; even configured overflow is screened and recorded as deferred. Only selected pairs receive M15/H1/H4/D history. Previous quote snapshots measure movement over intervals up to an hour, but movement does not change strategy scoring or approve entries. Set discovery false for explicit legacy configured-only mode.

Conversion crosses are derived from this account directory. A verified CCY/USD or USD/CCY pair is required; unavailable crosses are withheld rather than guessed or silently priced at one. Fresh discovery quotes are reused. USD liability/risk uses direct ask or inverse bid; positive P&L uses direct bid or inverse ask. Strategy v2 and forward-shadow v3 separate this corrected paper model from earlier experiments. Shared reservations persist the optional gain factor, and mark/exit accounting uses the applicable side. Existing saved single-factor orders retain their recorded model. Conversion rates remain frozen at proposal: subsequent currency movement and broker conversion charges are not modeled, so this is not broker-reconciled P&L.

Open Forex paper positions have an independent quote-monitoring stage, including pairs outside the shortlist or removed from the directory. Missing/stale discovery quotes trigger bounded pricing requests. History or directory failures cannot suppress this stage; unavailable or invalid marks remain explicit failures and the shared stale-position gate continues blocking new entries. Shadow positions use the same bounded quote loader.

Each scan journals full directory/quote/shortlist counts, per-instrument screen rows and structured rejections, quote coverage, membership deltas, technical/risk/reservation counts, stage duration and per-operation average/p95 latency. Batch provider failures are attributed to every requested pair. Available quota headers are retained; otherwise utilization is a scan-local estimate against the documented OANDA REST ceiling, not shared-IP or account-wide utilization. Unknown counts stay null. The Discord embed distinguishes the full screened universe from the deep-analysis shortlist.

`npm run probe:universe` makes only read-only directory/pricing requests and emits structured JSON; it does not download history, create paper orders or post Discord messages. The 2026-10-02 local preflight found both OANDA account ID and token absent: real account FX count and provider coverage are **unmeasured**. Synthetic fixtures verify full-directory screening, caching/deltas, non-G10 conversions, and independent position monitoring; they provide no market performance evidence.

## Offline chronological replay

Version 2 requires both `config.quoteToUsd` (liability/risk factor) and `config.gainQuoteToUsd` (proceeds factor) for non-USD quotes. Missing, nonnumeric or reversed factors block evaluation. USD-quoted instruments require unit conversion. Supply point-in-time assumptions from the historical dataset; a current FX rate cannot validate past paper outcomes.

`npm run backtest -- <dataset.json>` runs the unchanged M15/H1 strategy through the shared paper-risk and later-executable-quote lifecycle. The JSON input contains one `instrument`, `accountEquityUsd`, `config`, optional shared `policy`, `m15Bars` with `time`, `completedAt`, `complete: true`, and OANDA-style `mid` OHLC fields, plus strictly chronological `observations`. Each observation has `asOf`, an executable `{ bid, ask, time, quality: "executable" }` quote, and `context` containing point-in-time `sessionDate`, `h1Bars`, and a fresh source-backed `catalystReview`. Include explicit `quoteToUsd`, `roundTripFeesPerUnit`, and `slippageReservePerUnit`; the replay never downloads data. A synthetic test validates mechanics only. No licensed historical FX dataset, untouched holdout result, calibrated fill model, or profitability evidence is included.

Optional scheduled-event screening: set FOREX_CATALYST_SOURCE=finnhub and FINNHUB_API_KEY to request Finnhub's Premium Economic Calendar once per OANDA practice scan. The adapter maps common ISO currency codes (including TRY, MXN, HKD, SGD, Nordic and Central European currencies, and several Asian currencies) to country/region events and blocks pairs for medium/high events over the requested market date and adjacent provider-local dates; this conservative full-day blackout avoids assuming undocumented time-zone semantics. Unknown impact/data, missing credentials, unsupported currency mapping, or provider failure blocks clearance. Low-impact events are informational only. The feed does not classify company/token news, sentiment, futures exchange notices, or event surprise; it is not a substitute for broader market-calendar validation. `manual` remains default, so no Finnhub request occurs unless explicitly selected.
