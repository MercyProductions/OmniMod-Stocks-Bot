# Provider capability matrix

Updated: 2026-09-30. This is a source-code audit of the current six-bot workspace, not confirmation that any account has a paid entitlement. A provider appearing here means code can request that data; it does not mean credentials are configured, the request has succeeded, or the feed is licensed for commercial redistribution. Bots are research and paper-only. No broker/exchange order route is enabled.

The shared Finnhub Economic Calendar adapter used by Forex, Futures, Options, and ETFs/ETPs caches the raw response for five minutes in an atomic JSON file under `shared/data` by default. A same-host file lock prevents duplicate cold-cache requests across these local runners; each bot still computes its own instrument-country mapping and event gate. Cache operations are distinguished from network requests in diagnostics. The cache key is a hash of the API token and covered date range; token values are not persisted. Expired or malformed data is refreshed, and a failed refresh does not use stale data to clear catalyst gates. GET retries now honor numeric/date `Retry-After` for HTTP 429, 5xx, and transient network failures, with at most three attempts and fail-closed deferral beyond 10 seconds. Finnhub documents HTTP 429 for exceeded plan limits, which differ by account; see its [API documentation](https://finnhub.io/docs/api/country) and [Economic Data pricing](https://api.finnhub.io/pricing-economic-data-api). This is quota-efficiency plumbing, not an entitlement check or event-feed completeness guarantee.

## SEC automated-access limit\n\n- Stocks paces SEC requests across `sec.gov` and its subdomains at one request start per 100 ms inside a process. The SEC publishes a total maximum of 10 requests/second and says excess traffic may be limited by source IP; therefore this local pacer cannot guarantee compliance if other applications or workers share the same egress IP. Sources: [SEC developer FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions), [SEC privacy and security policy](https://www.sec.gov/about/privacy-information).\n\n## Implementation evidence and known gaps

## Account-level decisions still required before a forward paper cohort

### Futures: authoritative session and contract-reference source

Databento's currently wired Futures paths do not provide an authoritative CME/CBOT/NYMEX/COMEX trading schedule, holiday/early-close decision, or broker-specific margin/liquidation rule. The official CME Reference Data API documents contract specifications, product codes/symbols, trading schedules, and instrument lifecycle dates (first/last trade, notice, delivery, settlement), but CME states that access is provisioned by request. The public CME trading-hours/holiday page is useful for manual verification but is not an authenticated machine-readable schedule adapter in this project. Therefore session timestamps and settlement reviews remain supplied inputs and must not be described as exchange-verified. Before replacing them, obtain the relevant CME Reference Data access and licensed-use terms, then map its schedule/product and lifecycle rows to each dated contract and fail closed on missing or stale data.

### Options universe capability boundary

The official Tradier chain endpoint requires a single underlying symbol and expiration; its security-search endpoint is a partial-match lookup over securities and is not a ranked options-liquidity screener. The present bounded design consumes fresh delivered Stocks/ETF-ETP primary signals (or explicit manual inputs), then requests chains only for those underlyings. Expanding beyond those signals requires a qualified, timestamped underlying shortlist from an existing primary scanner, or a separately verified provider that exposes a suitable broad options/underlying screening capability with acceptable licensing, coverage, quotas, and cost. Do not query Tradier search with brute-force symbol fragments and mistake the result for a complete universe. No new vendor is recommended until that exact capability and account permission are verified.
