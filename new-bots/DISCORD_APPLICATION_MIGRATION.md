Operational commands are guild-scoped, ephemeral and restricted to Manage Server members, with the same check repeated at runtime. Neither Message Content nor Administrator permission is required.

Each market keeps its own `.env`, token, client ID, guild/channel IDs, app entry, scheduler state, logs, heartbeat, scan journal and process lock. A child scan retains its existing working directory and environment, market/provider code, risk ledger and journals. One child at a time per bot; a failed scan must not disconnect the parent application or another bot. Bot delivery must verify identity and destination and must not fall back to a webhook after an application error. Shared research publication still requires confirmed Discord delivery.

## Operating the four new applications

Install dependencies with `npm ci` from `new-bots`, then work from the individual market directory. `npm run setup` reports missing configuration and an installation link; `npm run register` registers only that market's configured guild commands; `npm start` connects the gateway and schedules the existing scanner. `npm run scan` invokes the scanner once. Do not launch a second scheduler beside the app. Tokens belong only in the ignored local `.env` or injected environment. Keep `OMNIMOD_LIVE_TRADING_ENABLED=false`.

Commands under `/forex`, `/futures`, `/options` and `/etfs`: `status`, `providers`, `lastscan`, `scanstats`, `portfolio`, `signals`, `outcomes`, `stop`, `scan`, `delivery-test`. All require Manage Server in the configured guild and respond ephemerally. `stop` displays the paper emergency-stop setting; it does not change it or stop the process. `delivery-test` posts only to the configured market channel. Other scan/candidate/risk approvals remain unchanged.

Each app uses `data/discord-application.lock`, `data/discord-application.log` (bounded rotation), a per-process heartbeat and its existing scan journal. A startup lock is not proof that its process is alive. `npm run shutdown` requests graceful shutdown of that exact local lock owner on Windows or Unix: it stops the scanner, disconnects Discord, marks the heartbeat stopped and releases the lock. An expired request cannot stop a replacement owner. After an abnormal same-boot termination, inspect the recorded PID/host, possible scanner children and paper state before recovery. Missing market credentials remain a distinct provider limitation, not a Discord connection failure.

Treat PID lists as historical evidence, not permanent service identifiers.

`scripts/install-windows-discord-tasks.ps1` registers four separate `OmniMod-<bot>-Discord` tasks for the current user's sign-in (Interactive, Limited privileges, no stored password). The action opens a hidden launcher with an unlimited execution duration and ignores duplicate starts. The launcher uses an exclusive OS file handle and adopts an already-running process only after matching its bot/host, PID birth, executable and command. It never terminates an unrelated process. A recorded lock from a proven earlier OS boot is archived, not blindly deleted; paper-risk locks and positions are never cleared. Same-boot disappeared owners remain an explicit recovery error because an orphaned scanner may still exist. Task Scheduler retries failures at most three times, a minute apart; it does not override that lock gate. The policy is covered by nine Windows checks, including a real nonzero child exit. See [Microsoft task settings](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset?view=windowsserver2025-ps).

Run `npm run shutdown` inside the individual bot folder for maintenance. To start it again in PowerShell, use `Start-ScheduledTask -TaskName 'OmniMod-forex-Discord'` (substitute `futures`, `options`, or `etfs-etps`). A graceful stop leaves the task enabled for the next sign-in; `Disable-ScheduledTask -TaskName ...` disables that future trigger. The normal `npm start` remains available, with the same runtime duplicate lock. Do not use Task Scheduler's force-stop as a substitute for the project's graceful command. Paper positions are not closed by stopping the process. This is local Windows hosting, not a promise of availability while logged out, asleep or powered off. A real OS reboot/logoff recovery exercise remains unperformed.
