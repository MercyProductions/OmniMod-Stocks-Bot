# New bot projects: research and readiness

Reviewed 2026-09-24. The goal document's promotional return claims are treated as hypotheses, not evidence of a durable or retail-accessible edge. All projects stay read-only until separately validated and explicitly configured.

## Provider facts used in the implementation

- **Prediction markets:** Polymarket documents market-level fee schedules and a price-dependent fee formula; Gamma exposes the active schedule on each market. The bot now reads that schedule for fee-aware complete-set sizing and maker fee treatment. Kalshi's public market list exposes top prices, while exact fees depend on its product schedule/multipliers, so cross-platform comparisons remain gross and explicitly unverified. Sources: [Polymarket market discovery](https://docs.polymarket.com/market-data/discover-markets), [Polymarket market details and fee fields](https://docs.polymarket.com/market-data/market-details), [Polymarket fee formula](https://docs.polymarket.com/trading/fees), [Kalshi market listing](https://docs.kalshi.com/api-reference/market/get-markets), [Kalshi fee schedule](https://kalshi.com/fee-schedule).
- **Forex:** Current runner defaults to disabled and only accepts OANDA practice prices; Yahoo adapters require explicit permission attestation and are not imported by the runner. The OANDA branch is hard-coded to the practice host and has no order endpoint call. Availability of v20 accounts differs by OANDA division. Sources: [OANDA v20 introduction](https://developer.oanda.com/rest-live-v20/introduction/), [OANDA development guide](https://developer.oanda.com/rest-live-v20/development-guide/).
- **DeFi yield:** The scanner reads the public DeFiLlama pool dataset and restricts results to configured lending projects, stablecoin-tagged pools, chains, and minimum TVL. Its provider fields are discovery inputs; they are not live executable quotes or independent contract reviews. The official Aave documentation says a current supply APY depends on utilization and that withdrawal liquidity can constrain exits, so a displayed APY cannot be treated as guaranteed income. Sources: [DeFiLlama API docs](https://defillama.com/docs/api), [Aave market and reserve data](https://aave.com/docs/mcp/tools), [Aave supplier risks](https://aave.com/docs/mcp/safety).
- **On-chain inefficiencies:** The project has a read-only adapter for circular routes through Uniswap V2-compatible routers. It calls `getAmountsOut` at a pinned block and subtracts configured gas and slippage reserves. The default uses PublicNode's no-key Ethereum RPC endpoint and Uniswap's documented Ethereum Mainnet Router02 deployment; public endpoints can rate-limit or observe request metadata. Sources: [ethereum.org's node services list](https://ethereum.org/developers/docs/nodes-and-clients/nodes-as-a-service), [Uniswap V2 deployments](https://developers.uniswap.org/docs/protocols/v2/deployments), [Uniswap V2 Router02](https://github.com/Uniswap/v2-periphery/blob/master/contracts/UniswapV2Router02.sol).
- **Multi-asset:** The project now has a public Yahoo Chart adapter for timestamped daily and intraday bars across configured symbols. The feed is unofficial and potentially delayed; provider access and freshness still need routine network-backed checks. Options payoff math accepts user-supplied vertical-spread terms only; no chain is fetched. Tradier documents authenticated chain endpoints and 15-minute-delayed sandbox data, while Cboe prohibits automated extraction from its delayed-quote tables. Sources: [Tradier market data](https://docs.tradier.com/docs/market-data), [Tradier options chains](https://docs.tradier.com/reference/brokerage-api-markets-get-options-chains), [Cboe delayed quotes](https://www.cboe.com/delayed_quotes/all). IBKR requires its own paper-account setup and notes that simulated fills differ from live execution. Source: [IBKR paper trading](https://www.interactivebrokers.com/docs/tws-api/doc/notes-limitations/limitations/paper-trading).

## Current state

All five projects have separate package manifests, source entry points, and README files. They use Node built-ins and require Node 22.9+ for `--env-file-if-exists`. Shared helpers append timestamped, credential-free observation snapshots and persist hashed semantic webhook alert keys under each project's ignored local `data/` folder. A separate optional Discord webhook can be configured per project, with a project display name and cooldown; blank webhook values disable sending. `npm start` runs non-overlapping repeated scans at the project's configured interval; `npm run scan` performs one pass. Built-in Node tests cover market-book ordering/depth, Polymarket fee-adjusted sizing, reviewed mapping expiry, Forex and multi-asset directional geometry, option-chain quote validation and defined-risk spread economics, conservative APY ranking, same-block quote economics, freshness, and durable webhook deduplication.

- DeFi yield: the public endpoint returned 17,187 pools; after correcting timestamp handling, 30 met the current configured pool screen. Pool rows lacked upstream timestamps, so their source age is unknown; the bot recorded response retrieval time only. No webhook was configured.
- Multi-asset: all seven configured symbols returned observations; three equity/ETF observations were stale at scan time, while current FX/futures observations produced directional scenarios. No webhook was configured.
- Forex: a public scan returned M15/H4/daily observations for all three configured pairs with separate frame watches; no bid/ask or executable-price claim is made. OANDA practice mode remains untested because no practice account is available. No webhook was configured.
- The on-chain live smoke route returned a same-block Ethereum Mainnet quote for nominal 100 USDC → USDT → WETH → USDC. The quote output was 99.27115 USDC (gross −$0.7289 on the nominal-$100 assumption); after the marked $25 gas and 1% extra-slippage placeholders, estimated net was −$26.7289, so it was not surfaced as an opportunity. No webhook was configured and no transaction was created. These checks do not validate investment performance.
- Tradier options-chain mode was implemented and its request/normalization/spread calculations passed mock-provider tests. It was not run against Tradier because no account token and explicit option expirations are configured. Its code path calls only options-chain market-data endpoints; it has no account/order calls.
- The on-chain adapter's PublicNode Ethereum endpoint returned chain 1, a recent block, and the configured Uniswap V2 quote at that block. The route's gross return was negative and it failed the cost gate as expected; no Discord destination was configured.

- `prediction-markets`: implements Polymarket binary book and equal-share complete-set screening, plus a paper market-making spread watch for sufficiently wide, fresh, two-sided books. Polymarket complete-set sizing now includes visible depth, market-specific taker fees, and per-outcome minimum notional; maker watches account for the market schedule's maker fee treatment. Cross-platform exact-rule mappings still show gross-only edge because the fetched Kalshi listing does not expose each market's effective fee multipliers. All signals retain fill, inventory, settlement and execution risks.
- `forex`: remains disabled until OANDA Practice is configured; when selected, the runner uses OANDA midpoint candles and bid/ask. It requires timeframe agreement for a combined bias and separately reports EMA watches with ATR invalidation and target. These scenarios are not calibrated probabilities. No OANDA practice token/account is configured.
- `futures`: dedicated futures project added with explicit index, energy, metal, rates, and currency continuous-symbol examples. The current context path is manual-only; the manual strategy requires active expiry and contract specifications. A licensed exchange-grade feed is not configured. Databento documents futures datasets and schemas; use requires a key and appropriate entitlements/licensing. Sources: [Databento futures data](https://databento.com/futures), [Databento futures conventions](https://databento.com/docs/examples/futures/futures-introduction/special-conventions-for-futures-on-databento).
- `multi-asset` options: discovered and fixed a temporal-dead-zone error in the Tradier branch: option chain processing referenced `observations` before initialization. Candidate construction now accepts only a fresh matching underlying and drops legs whose bid/ask quote times do not align within the configured skew. The chain universe and expirations remain manually configured; the adapter still has not been authenticated against a live Tradier account.
- `defi-yield`: implements a lending-pool and stablecoin discovery screen. It excludes stale rows only when the provider supplies an upstream timestamp; the current pool dataset omits it, so upstream age is marked unknown and the bot records its own retrieval time. It ranks by the lower of current and 30-day mean APY, displays base and incentive APY separately when available, and computes a base-only scenario when the provider supplies that field. It computes total-APY compound returns only as examples with supplied principal/holding period; net return is shown only with supplied round-trip costs. Provider TVL is not withdrawable liquidity. It does not inspect wallet holdings or send deposits.
- `onchain-inefficiencies`: supports offline JSON comparisons and live read-only EVM quote calls through configured V2-compatible routers. Live route reads verify the RPC chain ID and pin configured circular routes to one block; estimated net edge subtracts supplied gas and slippage reserve from an input-USD notional, with swap fees reflected in router output. A same-block Ethereum Mainnet smoke scan succeeded using a public RPC and the sample route; the route had negative gross edge. Default gas and slippage values are placeholders, not live execution-cost estimates. Quotes do not establish balances, token behavior, atomic execution, or MEV safety, so apparent edge can disappear.
- `multi-asset`: uses manually supplied observations only; its default universe file is a sample template, not a live price feed. Automated Yahoo Chart requests are disabled. Optional Tradier mode fetches configured option chains through read-only endpoints, screens fresh bid/ask legs by spread width and open interest, and surfaces one-contract debit-spread research candidates only when the underlying's 1-day and 5-day heuristic watch directions agree and the scenario payoff is positive. Tradier mode requires a token and explicit symbol/expiration rows and has not been live-tested; sandbox quotes are delayed. No order is placed. Option candidates are not forecasts; calculations exclude fees and early-assignment risk.

No Discord destination, OANDA practice credential, Tradier options token, recurring operating-system service, or broker interface is configured. The in-process scheduler runs only while its terminal/process remains open; these are not installed as background Windows services. The on-chain bot has a working Ethereum smoke route; its default costs remain placeholders and should be calibrated before treating any net estimate as useful. These are research alert projects, not live execution systems. Add separate `.env` files locally; `.gitignore` excludes them. Do not paste keys or webhook URLs into Discord or commit them.
