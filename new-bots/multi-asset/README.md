# Multi-Asset Research

This research scanner compares supplied observations for stocks, ETFs/ETNs, futures, and FX. `MARKET_SOURCE=manual` is the only enabled market source; set `MARKET_FILE` to timestamped inputs. The default 30-symbol sample preset is not populated with live data and must not be mistaken for a live scan. Automated Yahoo Chart access is disabled. An authorized provider adapter is required before scheduled live-data discovery can resume.

`examples/wrappers-and-macro-markets.json` is an optional 30-symbol screening preset covering broad and leveraged/inverse equity ETFs, gold/silver/oil and broad commodities, Treasury duration and inflation-protected funds, corporate/high-yield bonds, and volatility ETF/ETN products. Select it with `MARKET_FILE=examples/wrappers-and-macro-markets.json` and set `MAX_MARKETS=30` or higher. It is a hand-maintained sample, not a complete or live-validated universe. Leveraged/inverse products reset exposure daily and can diverge materially from a simple multiple over multi-day holds; an ETN also carries issuer-credit and product-structure risks. This scanner compares each wrapper's own prices and does not underwrite those mechanics or guarantee provider coverage. Bond funds have duration, credit, liquidity, distribution and premium/discount characteristics that this price-only screen does not analyze. ETF/ETN observations do not replace direct futures analysis.

Set `MARKET_SOURCE=manual` and `MARKET_FILE` to a JSON array of timestamped observations to use a different source. `MAX_MARKET_AGE_MINUTES` controls freshness; individual symbols can set `maxAgeMinutes`. Data-derived return and volatility scenarios are research context, not predicted prices, calibrated probabilities, or investment recommendations. Manual option payoff inputs only process explicitly supplied spread terms; they do not discover trades from a chain.

By default, the optional options input calculates expiration payoff bounds for defined-risk vertical spreads from supplied strikes and net premium. For an optional Tradier chain screen, set `OPTIONS_SOURCE=tradier` and add a Tradier market-data token to `.env`. `examples/options-universe.json` selects twelve underlyings: equity-index ETFs, gold/silver/oil, Treasury and high-yield bond ETFs, leveraged/inverse ETFs, and a volatility ETN. With `expiry: "auto"`, for each underlying the scanner reads listed expirations, then loads only the nearest date within `MIN_OPTION_DAYS_TO_EXPIRY` and `MAX_OPTION_DAYS_TO_EXPIRY` (defaults 7 and 45 days). This costs up to two sequential provider requests per underlying and does not search all strikes, expirations, or symbols. You can specify a single explicit `YYYY-MM-DD` expiry. The scanner rejects invalid, crossed, old, future-dated, mismatched, or thin quotes, and proposes one-contract call or put debit-spread research candidates only when 1-day and 5-day underlying watches agree. Underlying bars and option quote timestamps must be within `MAX_OPTION_UNDERLYING_SKEW_MINUTES` (default 15); otherwise candidates are withheld. It never accesses account or order endpoints. Tradier sandbox quotes are delayed; real-time stock/options data requires the appropriate Tradier brokerage account and entitlement. Confirm current rate limits and distribution terms with Tradier before scaling or redistributing. Set quote-age limits that fit the selected feed. Chain candidates use quoted leg prices and a heuristic underlying scenario; expiration payoff does not value the option before expiration and excludes fees, additional slippage, early assignment, and contract-specific exercise mechanics. This remains a configured sample, not a complete options-universe discovery bot or a validated strategy. The scanner does not scrape Cboe's delayed-quote web tables. Keep tokens local and never commit `.env`.

Run with Node 22.9+. No broker account is connected and no order is placed. A future IBKR paper adapter would require Client Portal Gateway or TWS, account setup, and market-data permissions; paper fills can differ from live execution.
